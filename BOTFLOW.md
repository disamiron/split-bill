# BOTFLOW.md — Флоу бота в группах

## Общая идея

Бот — точка входа для всех участников группы. Его задача:
1. Объяснить как работает Split Bill (коротко, без воды)
2. Поддерживать актуальный список участников группы
3. Корректно обрабатывать мутации: вход/выход участников

---

## 1. Бот добавлен в группу

### Триггер
`message:new_chat_members` где `member.id === bot.id`

### Действия
1. `upsert` группы в таблицу `groups`
2. Регистрация пользователя, добавившего бота (`upsert_telegram_user`)
3. Добавление этого пользователя в `group_members`
4. **Приветственное сообщение** (см. ниже)
5. **Запрос прав админа** (см. секцию 4)

### Приветственное сообщение

```
💸 Split Bill подключён!

Как это работает:
1. Каждый участник открывает приложение (кнопка ниже)
2. Кто-то создаёт счёт и выбирает участников
3. Все видят свою долю и отмечают оплату

👉 Чтобы начать — нажмите кнопку и откройте приложение.

[💸 Открыть Split Bill]
```

**Принципы сообщения:**
- Без лишних приветствий и эмодзи-спама
- 3 шага — ровно столько, чтобы понять суть
- Акцент: нужно **открыть приложение** каждому участнику
- Одна кнопка, одно действие

## 2. Новый участник вошёл в группу

### Триггер
`message:new_chat_members` где `member.id !== bot.id` и `member.is_bot === false`

### Сценарий A: Бот — админ (слушает события)

Бот получает событие автоматически.

**Действия:**
1. `upsert_telegram_user` для нового участника
2. Найти группу по `telegram_chat_id`
3. Добавить в `group_members` (upsert, идемпотентно)
4. **Отправить короткое сообщение:**

```
👋 {first_name}, добро пожаловать!
Открой приложение, чтобы участвовать в разделении счетов:

[💸 Открыть Split Bill]
```

**Почему приветствуем каждого:** новый участник не видел первое сообщение бота. Ему нужно понять, что делать.

### Сценарий B: Бот НЕ админ

Telegram может не доставлять `new_chat_members` событие боту без прав админа (зависит от настроек группы, privacy mode).

**Фоллбэк:** участник регистрируется при первом открытии Mini App (уже работает через `upsert_telegram_user` на фронтенде). Бот не отправляет приветствие — это ОК.

## 3. Участник покинул / удалён из группы

### Триггер
`message:left_chat_member`

### Сценарий A: Бот — админ

**Действия:**
1. Найти группу и пользователя в БД
2. Удалить из `group_members`
3. **Не отправлять сообщение** — не спамим, уход из группы это нормально

**Важно:** Не удаляем пользователя из `users` и не трогаем его записи в `bill_participants`. Долги остаются — это финансовые данные. Участник просто перестаёт быть членом группы и не появляется в списке при создании нового счёта.

### Сценарий B: Бот НЕ админ

Бот может не получить событие. Участник остаётся в `group_members` — «призрак».

**Фоллбэк:**
- При создании счёта фронтенд показывает список из `group_members`
- «Призраки» не критичны — они просто видны в списке участников
- Периодическая синхронизация (TODO, опционально): при открытии Mini App можно сверять список с реальным через API

## 4. Права админа

### Зачем нужны
- Гарантированное получение событий join/leave (без privacy mode ограничений)
- Доступ к `getChatMemberCount` и `getChatAdministrators` (для диагностики)
- Возможность в будущем: пинить сообщения, удалять свои старые сообщения

### Флоу запроса прав

**При добавлении бота** (через 3 секунды после приветствия, отдельным сообщением):

```
💡 Совет: дайте боту права админа — тогда я смогу автоматически отслеживать кто вошёл и вышел из группы.

Без прав админа всё тоже работает — просто каждому нужно будет открыть приложение самостоятельно.
```

**Принципы:**
- Не требуем, а рекомендуем
- Объясняем разницу: с правами и без
- Не блокируем работу — приложение работает в обоих случаях

### Проверка прав

При получении события бот может проверить свой статус:
```typescript
const me = await ctx.api.getChatMember(chatId, ctx.me.id);
const isAdmin = me.status === 'administrator' || me.status === 'creator';
```

Это можно использовать для:
- Решения отправлять ли приветствие новому участнику (если не админ — событие и так может не прийти)
- Логирования для отладки

## 5. Синхронизация участников (с правами админа)

### Когда запускать
- При открытии Mini App из группы (опционально, не MVP)
- По команде `/sync` от админа группы (опционально)

### Как работает
1. `getChatMemberCount(chatId)` — получить количество
2. Сравнить с количеством в `group_members`
3. Если расхождение — можно предложить пересинхронизацию

**Ограничение:** Telegram API не даёт получить полный список участников группы. Только `getChatAdministrators`. Поэтому полная синхронизация невозможна — мы полагаемся на события + регистрацию через Mini App.

## 6. Матрица: что работает с/без прав админа

| Функция | Админ | Без админа |
|---|---|---|
| Приветствие при добавлении бота | ✅ | ✅ |
| Авто-регистрация новых участников | ✅ | ❌ (через Mini App) |
| Приветствие новым участникам | ✅ | ❌ |
| Удаление ушедших из group_members | ✅ | ❌ (призраки) |
| Создание счетов | ✅ | ✅ |
| Оплата долей | ✅ | ✅ |
| Realtime обновления | ✅ | ✅ |

**Вывод:** Ядро функциональности (счета, оплата) работает без прав админа. Админ-права улучшают UX автоматической синхронизацией участников.

## 7. Edge Cases

### Бот удалён из группы
- Триггер: `message:left_chat_member` где `member.id === bot.id`
- Действие: **ничего не делаем** с данными. Группа и участники остаются в БД. Если бота добавят обратно — всё подхватится заново через upsert.

### Бот добавлен повторно
- Upsert группы — обновит title если изменился
- Приветственное сообщение отправляется заново — это нормально, могут быть новые участники

### Участник вышел и вернулся
- При выходе: удалён из `group_members`
- При входе: добавлен обратно через upsert
- Его старые `bill_participants` записи не тронуты — история сохранена

### Приватная группа vs супергруппа
- В обычных группах (`chat_id` < 0) — бот может не получать все события без админа
- В супергруппах — privacy mode более строгий
- Наш подход покрывает оба случая через фоллбэк на регистрацию через Mini App

### Пользователь заблокировал бота
- Бот не может отправить личное сообщение
- В группе бот всё ещё видит пользователя и может с ним работать
- Не влияет на функциональность Split Bill
